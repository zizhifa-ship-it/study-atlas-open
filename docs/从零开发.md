# 和学习图谱一起学开发

先体验自动流程：连接 AI 后，只粘贴一个公开 YouTube 链接，网站自动识别、分类、写笔记并保存。实现入口是 `app.js` 的 `smartImportModal`，后端是 `POST /api/import`，后台处理在 `importer.py`。没有字幕时保留记录等待补充，不凭标题生成学习笔记。

下面按功能拆开学习。目标不是一次记住所有代码，而是按 **分类 → 视频 → 笔记**，每次理解一个功能怎样从页面保存到文件。

## 第 1 课：先使用自己的作品

启动项目后，进入“网络工程”，新建子分类“网络协议”。先不要改代码。

观察这条路径：

```text
在网页填分类 → 点击保存 → app.js 发出请求
→ server.py 校验资料 → 写入 data/library.json → 页面更新
```

前端负责你看到的页面和按钮；后端负责接收请求并保存；JSON 是一种可以直接阅读的数据格式。

## 第 2 课：分类是怎样表示的

打开 `data/library.json`，找到 `categories`。

```json
{
  "id": "network-basics",
  "name": "网络基础",
  "parentId": "network",
  "color": "green",
  "description": "IP、OSI 模型、网络协议与常用设备。"
}
```

`id` 是程序用来识别分类的编号；`name` 给人看；`parentId` 指向上级分类。`parentId` 为 `null` 就是一级分类。

接着在 `app.js` 搜索这几个函数：

| 函数 | 负责什么 |
| --- | --- |
| `children` | 找到一个分类的直接子分类 |
| `categoryPath` | 从下级一路找到上级，组成分类路径 |
| `descendants` | 找出当前分类及它下面的所有分类 |
| `categoryCard` | 把分类数据变成页面上的卡片 |
| `categoryModal` | 收集输入并保存分类 |

**动手练习：** 在网页中创建“网络工程 → 网络协议”，保存后查看 JSON 是否出现新记录。尝试将它改名为“常用网络协议”。

## 第 3 课：一个视频怎样属于某个分类

先在网页里收藏一条自己的课程链接，再打开 `videos` 中对应的记录。下面是虚构的数据结构示例，网址不对应真实课程。

```json
{
  "title": "网络基础示例课程",
  "url": "https://example.com/network-basics",
  "categoryId": "network-basics",
  "tags": ["网络入门", "IP 地址", "OSI", "ICMP"],
  "status": "learning"
}
```

这里省略了其他字段。`categoryId` 把视频和分类连接起来。`tags` 可以让一个视频同时关联多个知识点，`status` 记录学习状态。

`videoModal` 从表单取得输入，`canonicalURL` 统一常见链接格式，`videoCard` 负责显示卡片。同一个 YouTube 视频，即使是 `youtu.be` 短链接，也会整理成相同链接，减少重复收藏。

**动手练习：** 给已有视频新增一个标签，再把状态改成“已学完”。刷新页面，检查标签和状态是否还在。

## 第 4 课：给视频增加笔记

打开视频，新增一条时间点笔记，时间填写 `4:25`。

笔记的数据形状是：

```json
{
  "id": "由程序生成的唯一编号",
  "timeSec": 265,
  "text": "写下你自己的理解。",
  "createdAt": "创建时间"
}
```

时间以秒保存：`4 × 60 + 25 = 265`。显示时由 `timeLabel` 还原成 `4:25`。点击时间点时，`jumpURL` 为支持的平台构造跳转链接。

在 `app.js` 找到 `noteModal` 和 `detailPage`，分别看“输入笔记”和“展示笔记”。`searchPage` 会把笔记正文也放进搜索范围。

**动手练习：** 写一个问题，例如“ICMP 和 TCP 有什么区别？”，保存后回到顶部搜索“ICMP”。搜索会找到包含这条笔记的视频。

## 第 5 课：认识一次保存请求

在 `app.js` 找到 `save`，核心逻辑是：

```js
state.library = await request('/api/library', {
  method: 'PUT',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify(next)
});
```

`PUT` 表示提交这份修改后的资料。`JSON.stringify` 把对象转换成文字，后端再解析为数据。`await` 表示等待保存结果；成功后才更新界面。

在 `server.py` 找到 `do_PUT`，继续看 `LibraryStore.save`：先校验内容和版本，再备份原文件，最后用临时文件替换正式文件。这样错误数据不会直接覆盖原资料，两个页面同时修改时也能检测冲突。

**动手练习：** 打开两个知识库页面。先在第一个页面保存，再在没有刷新的第二个页面修改。第二次保存会提示版本冲突。先复制还没保存的文字，再刷新页面后重新填写。

## 第 6 课：把项目放进 GitHub

Git 是电脑上的版本记录工具，GitHub 是保存 Git 仓库的在线平台。

如果这个项目已经在你的 GitHub 里，后续换电脑时先下载它：

```sh
git clone https://github.com/YOUR_USERNAME/study-atlas-open.git
cd study-atlas-open
python3 server.py --open
```

私有仓库需要先完成 GitHub 的 Git 身份验证。浏览器已登录或 Codex 已连接 GitHub，不一定表示终端里的 Git 也已经登录。可以使用 GitHub Desktop 完成登录和克隆，或者按 GitHub 官方文档配置终端认证。

把 `YOUR_USERNAME` 换成项目所在的 GitHub 用户名。如果你自己从空文件夹开始开发，在 GitHub 创建一个空仓库，不勾选生成 README，再在本机执行：

```sh
git init -b main
git add .
git commit -m "创建视频学习知识库"
git remote add origin https://github.com/YOUR_USERNAME/study-atlas-open.git
git push -u origin main
```

这段命令用于**从空目录起步的练习**。已经克隆下来的项目，不要重复初始化或再次添加同名远程仓库。

源码、文档和匿名示例可以提交到开源仓库。个人学习资料不提交。修改程序后的提交方式例如：

```sh
git status
git add app.js styles.css server.py integrations.py
git commit -m "改进学习知识库功能"
git push
```

`git status` 看哪些文件变了；`git add` 选择本次要记录的内容；`git commit` 在本机留下一个版本；`git push` 才上传到 GitHub。改代码时也要选择对应的代码文件一起提交。

这里通过 Git 同步的是程序代码。`data/library.json` 和 `.local/` 已被忽略，里面的个人资料、API Key 和授权 token 不会上传。跨设备迁移个人学习资料时，使用自行保管的 JSON 备份；不要通过公开仓库存储它们。

参考：[GitHub 官方：把本机代码添加到 GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)。

## 之后可以自己加的功能

按难度递增练习：给分类增加排序；给视频增加星级；给笔记增加“待复习”标记；阅读 `integrations.py` 学习请求 AI 与 YouTube API；最后再考虑登录和跨设备同步。

每增加一个功能，都问自己四件事：数据多哪个字段，页面在哪里输入，后端怎样校验，刷新后能否重新读取。先把这四步走通，再继续下一个功能。
