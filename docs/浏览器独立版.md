# 浏览器独立版：iPad 直接调用 DeepSeek

在线地址：**https://zizhifa-ship-it.github.io/study-atlas-open/**

## 开始使用

1. 在 iPad Safari 打开上述地址，点击“连接 DeepSeek”。
2. 输入你自己的官方 API Key，点击“检查连接 / 读取模型”，选择账号实际可用模型，再点击“使用这个连接”。没有内置公共密钥；API 费用由自己的账号承担。
3. 导入 PDF、TXT、Markdown、字幕或原文转录。无论原文语言，都可以按选择的语言整理笔记。单份 PDF 最多 8 MB / 300 页，正文最多 80 万字符；扫描页需先 OCR。
4. AI 自动分类，生成康奈尔笔记、知识模块和复习问题，并另做一轮自查。自查在“质量、原文与 AI 自查”中展开，不占主要阅读区域；笔记会先保存，后续自查失败不丢已完成笔记。
5. 点击“知识脑图”查看结构，写下批注，或在“问问 DeepSeek”中继续对话。最近回答可保存为批注。
6. 选择“打印 / 存为 PDF”，在 Safari 打印预览中通过分享菜单存到“文件”或导入无边记。也可下载 Markdown、SVG 脑图及 JSON 备份。

可通过 Safari 分享菜单“添加到主屏幕”保留入口。访问网页和调用 AI 需要可用网络；Mac 可以关机。

## 数据与 API Key

- 静态网页由 GitHub Pages 提供。API 请求从当前设备直接发往固定的 `https://api.deepseek.com`，使用官方 `/models` 和 `/chat/completions`，不经项目代理。
- Key 默认只在当前页面内存，不保存到 IndexedDB、localStorage、sessionStorage、JSON 备份或 GitHub。刷新、关闭或清除连接后重新填写。不要把 Key 发到 Issues 或截图。
- 笔记、导入正文、批注和有效 AI 缓存在当前浏览器的 IndexedDB。网站没有统一的用户内容服务器或自动多端同步；公开网站不等于公开你的浏览器资料。
- 清除 Safari 网站数据、更换浏览器、设备或私密浏览模式可能使资料不可用。请定期导出 JSON，自行保管。
- 从电脑版迁移：在原网站导出 JSON，再在独立版“导入备份”；重复记录保留当前版本，连接密钥不会导入。

## 功能边界

- **视频链接可以收藏，但不保证自动取字幕。** YouTube / B站的跨域、登录及平台限制不能靠 API Key 绕过。需粘贴实际转录、上传字幕或讲义后再制作笔记；不根据标题编造内容。电脑完整版保留平台提取、本地语音识别和视频画面获取。
- PDF 在浏览器用 PDF.js 提取文字和页码，不把原 PDF 二进制发送给 DeepSeek；图片、扫描页与复杂公式不等同于已理解。正文仍需对照原件核对。
- 浏览器版侧重课程资料、AI 笔记、脑图、问答和批注；论文、学术路径的完整编辑仍在电脑或私有服务器版。导入的论文记录、研究路径可随 JSON 备份保留。
- 问答优先在本机检索相关笔记片段，并限制最近对话长度，降低重复发送全文的用量。长正文分段 / 分层处理，模型和内容匹配的有效缓存可复用；失败不自动重复发起付费请求。
- AI 自查不能保证事实正确。重要数字、公式、代码、实验结果请对照原来源。

## 发布与构建

```sh
python3 tools/build_browser_site.py
```

输出到 `_site-browser`。构建程序仅复制固定前端文件、共享的康奈尔 / 脑图组件与样式，绝不复制 `.local`、`data/library.json`、PDF 原件、日志或导出文件。PDF.js 版本及 SHA-512 完整性固定在 `browser/vendor.lock.json`；依赖随本站发布，不从第三方 CDN 动态执行代码。包含 Mozilla Apache-2.0 许可、项目许可与历史 MIT 许可。

`.github/workflows/pages.yml` 通过 GitHub Actions 构建并部署到 Pages。仓库 Pages 设置需选择 GitHub Actions，构建产物根目录含 `index.html`。后端文件不会被当作静态网站发布。

参考：[GitHub Pages 工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[DeepSeek API](https://api-docs.deepseek.com/api/create-chat-completion/)、[Mozilla PDF.js](https://mozilla.github.io/pdf.js/getting_started/)。

## 保存、继续与精练阅读

- 同一正文或相同来源链接再次导入会合并到原记录；仅收藏相同链接不会清空正文。刷新会恢复上次课程与阅读标签。
- 生成结果先落盘，再做独立自查。自查失败时笔记仍可读；重新连接后只继续未完成阶段。收到完整响应但格式不合规时，最多自动修复一次格式，不重新发送原资料。
- 同一任务快速重复点击、同时打开两个标签页，均有请求去重保护。网络中断、关闭页面等导致服务端结果未知时不会自动重发；继续前提示可能产生新请求。浏览器 API 不能查询已丢失响应的服务端结果，因此不能承诺此情况下绝无重复计费。
- Key 刷新后需要重新填写，但已保存笔记无需重新生成。先导入再连接时，已排队资料会自动继续。未连接也能阅读、批注与导出。
- 重点卡是预览，不删除原笔记；“完整笔记”保留全部说明。“我记得了 / 再看一次”只保存本地复习进度，不调用模型。复习间隔是可用的默认安排，并非个人记忆能力的精确预测。
- 现有长笔记不强制重新收费改写。可先用重点卡阅读；若要按精练标准重写，在“质量、原文与 AI 自查”展开区确认更新。旧总结与手写批注保留。
- 多设备仍需 JSON 备份迁移；清理网站数据、无痕会话结束或设备存储回收可能删除本机资料。建议定期导出。
